# GPT Translator — Mac용 Premiere CEP 패널

**SRT의 자막 번호와 타임코드를 원본 그대로 보관하고, 본문만 번역해 새 SRT로 저장하는 플러그인이야.** 번역은 OpenAI API로 처리하고, 잘못된 응답은 저장하기 전에 차단해. 기존 패키지가 제공되지 않아 요청한 설명을 바탕으로 새로 작성한 버전이야.

배포 버전: **1.0.0** · 작성일: **2026-10-08**

## 1. 설치

1. ZIP 전체를 압축 해제해. `Install_Mac.command`와 `GPT_Translator` 폴더의 상대 위치를 유지해 줘.
2. Premiere Pro를 완전히 종료해.
3. **`Install_Mac.command`를 실행**해. 사용자 계정의 CEP 폴더에 패널을 설치해.
4. Premiere를 다시 실행하고 **창 → 확장 프로그램 → GPT Translator**를 열어. 버전에 따라 메뉴에 `Legacy`가 표시될 수 있어.

별도 Node.js, npm, Python, VS Code, Copilot 설치는 필요하지 않아. Premiere에 포함된 CEP의 Node.js를 사용해. 설치 스크립트는 다운로드하거나 관리자 암호를 요구하지 않아.

설치 대상 경로는 다음과 같아.

```text
~/Library/Application Support/Adobe/CEP/extensions/GPT_Translator/
```

개발용 미서명 CEP 패널이므로 설치 스크립트는 현재 사용자 **CSXS.11과 CSXS.12의 `PlayerDebugMode`를 문자열 `1`로 설정**해. 이 설정은 해당 런타임의 다른 미서명 CEP 확장에도 적용돼. 변경 전 값은 설치 폴더의 `INSTALLATION_INFO.txt`에 기록해. CSXS.13~15에 추측으로 설정을 추가하지 않아.

설치가 차단되거나 직접 설치하고 싶으면 [Mac 설치·호환성 안내](docs/CEP_COMPATIBILITY.md)를 확인해 줘. 기존 설치가 있으면 삭제하지 않고 CEP 검색 경로 밖에 백업해.

### 직접 복사해서 설치할 때

Finder의 `Cmd + Shift + G`로 아래 경로를 열고, `GPT_Translator` 폴더를 넣으면 돼. 기존 폴더가 있다면 먼저 별도 위치에 보관해 줘.

```text
~/Library/Application Support/Adobe/CEP/extensions/
```

CEP 설정은 터미널에서 다음 두 명령으로 적용해. 설치 프로그램을 사용했다면 다시 실행할 필요 없어.

```bash
defaults write com.adobe.CSXS.11 PlayerDebugMode -string 1
defaults write com.adobe.CSXS.12 PlayerDebugMode -string 1
```

Adobe 공식 문서가 설명하는 [CEP 설치 폴더와 미서명 확장 실행 방식](https://github.com/Adobe-CEP/CEP-Resources/blob/master/CEP_12.x/Documentation/CEP%2012%20HTML%20Extension%20Cookbook.md)을 따른 설정이야.

## 2. 사용

1. Premiere에서 번역할 자막을 **SRT로 내보내거나 기존 SRT를 준비**해.
2. 패널에서 **SRT 열기**를 눌러 파일을 선택해. 유효한 파일이면 자막 개수·기본 요청 횟수·인코딩을 표시해.
3. 원본 언어와 번역 언어를 골라. 원본은 자동 감지가 기본이고 번역 언어는 영어가 기본이야.
4. 본인의 **OpenAI API 키**를 입력해. 채팅이나 소스 코드에 키를 붙여 넣을 필요는 없어.
5. 필요하면 말투·고유명사 지침을 넣어. 예: `자연스러운 구어체. NOWZ는 영문 그대로 유지.`
6. **API로 번역**을 눌러. 모든 묶음과 마지막 보존 검사가 통과하면 저장 버튼이 활성화돼.
7. 처음 5개 자막의 미리보기를 보고 **번역 SRT를 새 파일로 저장**해. 전체 문장 검수는 저장한 SRT와 실제 영상을 함께 보며 진행해 줘.
8. 저장한 SRT를 Premiere로 가져와 자막 트랙에 배치해.

기본 모델은 `gpt-4.1-mini`야. OpenAI 공식 문서에서 [Responses API와 Structured Outputs 지원](https://developers.openai.com/api/docs/models/gpt-4.1-mini)을 확인한 모델을 사용했어. 다른 모델 이름을 직접 입력할 수 있지만, 해당 계정에서 사용 가능하고 같은 API 출력 규격을 지원해야 해. 모델 이름을 바꿨다고 접근 권한이 생기는 것은 아니야.

**자동 번역은 OpenAI API 사용료가 발생하고, ChatGPT 구독과 별도야.** [OpenAI의 결제 구분 안내](https://help.openai.com/en/articles/9039756-managing-billing-for-chatgpt-and-the-api-platform)를 참고해. 패널을 열거나 SRT를 읽는 동작은 API를 호출하지 않아. `샘플 열기`도 읽기만 하며, 그 뒤 번역 버튼을 누르면 실제 요청이 발생해.

번역 버튼을 누르면 자막의 본문·내부 ID·언어·말투 지침을 OpenAI로 보내. 원본의 자막 번호, 시간 필드, 파일 경로, 영상 파일은 요청에 넣지 않아. 본문에 인물 이름 등 정보가 포함되어 있으면 그 본문은 함께 전송돼.

## 3. 싱크를 보호하는 방법

| 단계 | 처리 |
| --- | --- |
| 원본 분석 | 숫자 번호와 타임코드를 다시 계산하지 않고 원문 문자열의 위치를 보관해. |
| 내부 ID | `c000001` 같은 고유 ID를 부여해. 원본 자막 번호가 중복되어도 구분돼. |
| 순차 처리 | 최대 **50개**씩 번역해. 마지막 묶음이나 긴 본문은 더 작은 묶음이 될 수 있어. |
| 길이 제한 | 한 묶음의 본문 길이를 최대 12,000 UTF-16 코드 단위로 제한해. 자막 하나가 이를 넘으면 첫 API 호출 전에 거부해. |
| API 응답 | 엄격한 JSON 스키마를 요청하고, 실제 반환 상태·거절·중도 종료·JSON 형식도 별도로 확인해. |
| 일대일 검사 | 개수뿐 아니라 **각 위치의 ID, 중복, 누락, 순서**를 확인해. 하나라도 다르면 중단해. |
| 본문 검사 | 빈 본문, 자막을 쪼개는 빈 줄, 시간표기 화살표, NUL/BOM 삽입, 서식 태그 변경을 차단해. |
| 원본 복원 | 원본의 본문 구간만 번역문으로 교체해. 번호·타임코드·외부 구분선은 원본 문자열에서 가져와. |
| 최종 검사 | 완성된 SRT를 다시 파싱해 번호·타임코드·구조가 일치하는지 확인해. |
| 파일 저장 | 완성된 임시 파일을 검증한 뒤 새 파일 이름으로만 공개해. 원본과 기존 결과의 덮어쓰기를 허용하지 않아. |

50개 분할만으로 응답 잘림이 사라지는 것은 아니야. 출력 토큰 한도나 서버 오류 때문에 중단될 수도 있으므로, **완료 여부 검사와 저장 차단**까지 적용했어. OpenAI도 구조화 응답에서 [거절·출력 한도·불완전한 응답을 처리하도록 안내](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses)하고 있어.

CRLF/LF/CR 줄바꿈, 초기 BOM, UTF-8과 BOM이 있는 UTF-16 LE/BE를 지원해. 원래 본문 안에 있던 줄바꿈은 해당 자막의 방식으로 복원하고, 번역 줄이 늘어나면 해당 자막의 줄바꿈 방식을 사용해. UTF-8로 읽을 수 없는 CP949/EUC-KR 파일 등은 문자를 임의로 바꾸지 않고 다시 저장하라는 오류를 표시해.

## 4. 실패·취소·재시도

| 상황 | 결과 |
| --- | --- |
| 개수·ID·순서가 달라짐 | 번역을 중단하고 새 결과 파일을 만들지 않아. |
| API 출력이 잘리거나 거절됨 | 부분 응답을 완성된 번역으로 처리하지 않아. |
| 요청 제한 또는 일시적 서버 오류 | 해당 묶음만 최대 두 번 재시도해. |
| 결제 잔액·권한·API 키 오류 | 자동 반복 없이 중단해. |
| 응답 대기 120초 초과·연결 끊김 | 처리 여부가 불확실하므로 자동 재전송하지 않아. |
| 사용자가 취소 | 진행 중 요청을 닫고, 늦게 도착하는 응답도 버려. 이미 처리된 요청에는 비용이 발생할 수 있어. |
| 같은 원본을 다시 번역하다 실패 | 이전에 검사를 통과한 결과가 있으면 보존해. 화면에서 이전 결과임을 알려 줘. |
| 저장 전에 원본 내용이 바뀜 | SHA-256 비교로 감지하고 저장을 중단해. 새 원본을 다시 열어 줘. |
| 저장 대상 파일이 이미 존재 | 기존 파일을 건드리지 않고 다른 이름을 요청해. |

중단한 작업의 부분 결과는 디스크에 저장하지 않아. **전체 번역을 새로 시작하면 완료했던 앞부분도 다시 API로 보낼 수 있어.** 기존 성공 결과를 다시 저장하는 것은 API를 호출하지 않아. 이번 버전에는 작업 재개용 디스크 캐시가 없어.

원본 입력은 최대 10 MiB까지 허용해. 번역 결과가 원본보다 커지는 것은 허용해. 새 파일의 공개 단계에는 운영체제의 하드 링크를 사용하므로, 이를 지원하지 않는 일부 외장 드라이브·네트워크 폴더에서는 Mac 내부 디스크에 저장해야 해. 실패 시 원본을 덮어쓰는 방식으로 우회하지 않아.

## 5. 이 버전의 범위와 확인하지 못한 부분

이 플러그인은 **SRT 입력 → 본문 번역 → 새 SRT 출력**을 수행해. 영상/오디오 파일 분석, 프레임레이트 변환, 실제 촬영본 재싱크, Premiere 타임라인의 직접 수정, 자막 트랙 자동 생성 기능은 포함하지 않아.

시간 필드를 보존하므로 원래부터 어긋난 자막의 싱크는 그대로 남아. 또한 모델이 ID는 유지하면서 문장을 잘못 번역하거나 서로 잘못 대응시키는 의미상의 오류까지 기계적으로 보장할 수는 없어. 번역 표현·화자 관계·고유명사·읽기 속도는 영상과 함께 검수해 줘.

키는 설정 파일·`localStorage`·`sessionStorage`에 저장하지 않아. 패널 실행 중 메모리와 입력창에서만 사용하고 지우기 버튼이나 패널 종료 시 입력창을 비워. 키는 Node HTTPS 요청의 Authorization 헤더로만 보내고, 원문이나 키를 로그로 남기지 않아. 요청은 `store:false`를 지정하지만 이것을 서비스 제공자의 모든 데이터 보관이 없다는 뜻으로 해석하면 안 돼.

**실제 Mac 설치, Premiere 호스트 실행, 사용자 계정의 유료 OpenAI API 번역은 제작 환경에서 실행하지 못했어.** 모의 호스트와 모의 API 테스트는 실제 앱 실행을 대신하지 않아. 지원 대상으로 설정한 버전과 공식 근거는 [CEP 호환성 문서](docs/CEP_COMPATIBILITY.md), 실제 실행한 검사는 [검증 기록](docs/VERIFICATION.md)에 정리했어.

## 6. 파일 구성과 수정

| 파일 | 역할 |
| --- | --- |
| `Install_Mac.command` | Mac 사용자용 설치 및 기존 설치 백업 |
| `Uninstall_Mac.command` | 설치를 제거 위치의 백업으로 이동 |
| `GPT_Translator/CSXS/manifest.xml` | Premiere의 CEP 확장 등록 |
| `GPT_Translator/index.html`, `css/panel.css` | 한국어 패널 화면 |
| `GPT_Translator/js/app.js` | 파일 선택·번역 진행·저장·취소 연결 |
| `GPT_Translator/lib/srt.js` | 원본 보존 파싱·ID 검증·본문 복원 |
| `GPT_Translator/lib/openai.js` | OpenAI 연결·스키마·응답·재시도 |
| `GPT_Translator/lib/jobs.js` | 순차 번역 작업과 취소 처리 |
| `GPT_Translator/lib/files.js` | 인코딩·원본 변경 검사·새 파일 저장 |
| `GPT_Translator/samples/sample_ko.srt` | 5개 자막의 테스트용 입력 |
| `tests/` | 합성 데이터로 실행하는 자동 검사 |

말투는 먼저 패널에서 조정해. 공통 번역 지침을 코드에서 바꾸려면 `lib/openai.js`의 `SYSTEM_PROMPT`를 수정하면 돼. 타임코드를 API 입력으로 추가하거나 ID 검사를 없애는 수정은 피하는 것이 좋아.

### 개발자용 검사 실행

설치 사용자에게는 이 단계가 필요 없어. 소스를 수정한 개발자만 패키지 폴더에서 Node.js 18 이상으로 실행하면 돼.

```bash
npm test
node tests/panel-smoke.cjs
bash -n Install_Mac.command
bash -n Uninstall_Mac.command
```

외부 npm 의존성은 없어. 테스트는 실제 키를 읽거나 유료 API를 호출하지 않아. 실제 Premiere에서의 확인은 별도로, 제공된 5개 샘플의 읽기 → 번역 → 새 파일 저장 → 가져오기 순서로 진행해 줘.
