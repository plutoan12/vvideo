# GPT Translator 1.0.0 검증 기록

검증 기준일: 2026-10-08

## 결과를 읽는 기준

**자막 보존 로직과 실제 로컬 파일 저장은 실행해서 검사했어. OpenAI는 합성 응답을 반환하는 모의 연결을 사용했어.** 사용자 API 키를 읽거나 유료 번역을 요청하지 않았어.

제작 환경은 Linux, Node.js 24.19.0, Python 3.12.14야. 플러그인 코드는 CEP 11·12의 Node 환경을 대상으로 작성했지만 실제 Mac, Premiere, CEP 내장 Node에서 실행했다는 의미는 아니야.

## 자동 검사

`node --test tests/*.test.js` 결과: **92개 통과, 실패 0, 건너뜀 0**. 중첩된 개별 사례까지 포함한 Node 테스트 러너의 집계야.

| 영역 | 검사한 동작 |
| --- | --- |
| 원본 파싱 | 초기 BOM, UTF-16 문자열 위치, CRLF/LF/CR, 혼합 줄바꿈, 마지막 줄바꿈 유무 |
| 시간·번호 보존 | 앞자리 0, 중복·비연속 번호, 겹치는 시간, 긴 시간값, 시작/종료 범위 검사 |
| 응답 대응 | 동일 개수의 역순 응답, 중복·누락·알 수 없는 ID, 잘못된 본문 형식 차단 |

| 키 보호 | 오류에서 원시 헤더·키·서버 본문을 노출하지 않음 |

## 패널 연결 검사

최종 실행 결과: **통과**. 외부 네트워크 호출은 차단한 상태에서 검사했어.

`node tests/panel-smoke.cjs`는 실제 `js/app.js`, 자막·작업 엔진, 실제 임시 로컬 SRT 파일을 사용해. 화면의 DOM, CEP의 네이티브 파일 선택 창, 번역 제공자만 모의 객체로 제공하는 방식이야.

이는 실제 브라우저 화면 렌더링이나 Premiere 호스트 검사가 아니야. Playwright 패키지는 있었지만 Chromium 실행 파일이 없어 실제 브라우저 실행을 완료하지 못했고, 외부 설치 없이 Node VM 방식으로 동작 연결을 확인하도록 구성했어. 최종 배포본의 해당 검사는 추가 npm 의존성이 없어.

검사 대상은 CEP가 없을 때 안내, 연결 초기화, 원본 열기, 키 미입력 차단, 번역 완료, 새 SRT 저장, 기존 파일 덮어쓰기 차단, 응답 순서 오류, 요청 중 취소, 이전 성공 결과 보존, 키 지우기와 종료 처리, 자막을 HTML로 실행하지 않는 미리보기야.

## 설치 패키지

다음을 검사했어.

- `Install_Mac.command`, `Uninstall_Mac.command`가 `bash -n`을 통과함.
- 두 스크립트의 실행 권한이 `755`로 설정됨.
- `manifest.xml`이 XML 파싱과 Adobe의 실제 `ExtensionManifest_v_7_0.xsd` 검증을 통과함.
- 번들·패널·설치기·패키지 버전이 `1.0.0`으로 일치함.
- Linux에서는 Mac 전용 스크립트가 설치 또는 설정 변경 전에 중단함.
- ZIP에는 설치 폴더, 두 실행 파일, 사용 안내, 샘플, 소스와 검사가 포함됨.

공식 매니페스트 스키마: [Adobe CEP v7 XSD](https://github.com/Adobe-CEP/CEP-Resources/blob/master/CEP_7.x/ExtensionManifest_v_7_0.xsd)

## 검토에서 수정한 문제

1. **번역 결과가 10 MiB를 넘으면 저장이 막히는 문제.** 원본 파일의 읽기 제한과 자체 생성한 출력 파일의 검사를 분리하고, 큰 번역문 저장 회귀검사를 추가했어.
2. **정상 CRLF 번역 응답을 거부하는 문제.** API 본문의 CRLF/CR을 LF로 정규화해 검사한 뒤 원본 자막의 줄바꿈으로 복원해.
3. **잘못된 HTTP UTF-8 바이트를 대체 문자로 받아들일 수 있는 문제.** 엄격한 UTF-8 디코더로 변경하고 잘못된 바이트 및 정상 멀티바이트 분할 사례를 검사했어.
